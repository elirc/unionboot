Q201 — family JSON document projection and type policy, scenario 1: scalar-name

Task
Extract name as SQL text, ordered by id.

Dialect
SQLite 3.49.1 using Node node:sqlite DatabaseSync. JSON/FTS5, generated columns, PRAGMAs, rowid, date functions and EQP syntax/text are SQLite-specific. This is a related scenario within its family, not a claim of a wholly unrelated concept.

Fresh seed (foreign_keys=ON)
CREATE TABLE docs(id INTEGER PRIMARY KEY,body TEXT CHECK(json_valid(body)));INSERT INTO docs VALUES(1,'{"name":"Ada","age":30,"active":true,"city":null}'),(2,'{"name":"Bo","age":"20","active":false}'),(3,'{"name":"Cy","active":true,"city":"Rome"}');

Concrete example
The first result row on this seed is {"id":1,"name":"Ada"}.

Expected shape
Columns: id, name. Exact ordered rows, including NULL and duplicates:
[
  {
    "id": 1,
    "name": "Ada"
  },
  {
    "id": 2,
    "name": "Bo"
  },
  {
    "id": 3,
    "name": "Cy"
  }
]

Submission
Write SQL in starters/Q201.sql. The final statement returns the graded rows; preceding statements may change only this disposable database. Blank SQL returns [] and fails. No helper SQL implements a blank answer. Reference and starter use the same tests. Use ORDER BY for the stated output order.
