TS-NEXT — STRUCTURAL TYPESCRIPT CONTRACT LAB

750 new exercises; IDs 1969–2718; tech: ts. 50 families × 15 observably different public contracts. Not 750 unrelated algorithms. Variations alter recursive budgets, tuple dimensions, required key sets, allowed variants, or protocol states. The manifest records semanticKey and a public-contract SHA-256. Generator gates require family|semanticKey uniqueness and 15 distinct public contracts per family.

Architecture
Six files per exercise: prompts/<id>.txt, starters/<id>.ts, solutions/<id>.ts, tests/<id>.cjs, types/<id>.positive.ts, types/<id>.negative.ts. Starters keep the type API but throw TODO exercise <id>. Solutions are independent and never imported by starters. Exactly four @ts-expect-error cases per negative fixture; positive fixtures guard against any on solve and assert concrete return/key/tuple types.

Workflow
1. Read a prompt and implement its starter without changing the API.
2. node ts-next/verify.cjs --starters --id=1969
3. Reference: node ts-next/verify.cjs --id=1969
4. Inventory (no compiler/runtime): node ts-next/verify.cjs --inventory
5. Full suites (coordinator only during authoring): node ts-next/verify.cjs and node ts-next/verify.cjs --starters
--id N is also supported. Unknown/duplicate arguments and unknown IDs exit 2.

Strict gate
The existing local TypeScript 5.9.3 tsc CLI is required (never downloaded). strict, noUncheckedIndexedAccess, exactOptionalPropertyTypes, useUnknownInCatchVariables, noImplicitReturns and noEmitOnError are enabled. Both positive AND negative imports are rebound to the candidate. tsc must pass before any runtime test. Fixtures are compile-only. A compiler failure is never accepted as a blank control.

Exit codes and evidence
0: all runtime checks pass; 1: compiler passed but runtime grading failed; 2: setup/compiler/CLI failure. A valid blank control requires successful compiler followed by every selected runtime test failing with its exact TODO exercise ID. verification-solution.json and verification-starter.json record explicit scope and selected IDs; per-ID summary names and reports/<mode>-<id>.json preserve single-ID evidence. verification.log and blank-control.log append actual diagnostics. A single-ID report NEVER claims a full suite passed. Compiler scratch files are removed after each run.

Authoring and safety
Source: ../build-ts-next.cjs. It refuses an existing ts-next directory, uses exclusive writes, checks existing manifests for ID collisions, and never touches root integration. --inventory builds and checks inventory in memory without writing. No installs, network, commits, or publishing. No full suites were run by the author; the coordinator must run them sequentially on the memory-limited machine.

Domain notes
Template-literal transformations specify their exact ASCII or placeholder domain. Tuple algebra rejects widened arrays. Mapped object APIs assume exactly their declared own string fields unless otherwise specified. Assertions bridge runtime iteration with types, not validation gaps. Type fixtures are regression contracts, not a proof against deliberate type escapes.
