FRONTEND AND WEB FOUNDATIONS
260 self-study questions with reference answers; not executable exercises.

FS001 | Semantic HTML | junior
Q: When should a clickable control be a button rather than a link?
A: Use a button for an action such as submitting, toggling, or opening a dialog. Use an anchor with an href for navigation. Native elements provide keyboard behavior and browser affordances that custom clickable containers otherwise need to reproduce.

FS002 | Semantic HTML | junior
Q: How would you structure headings on a product detail page?
A: Use headings to express the document hierarchy, not to select a font size. Give the page a clear primary heading and use subordinate headings for related sections. Screen-reader users can navigate this outline independently of the visual layout.

FS003 | Semantic HTML | junior
Q: Why does a search field need a label when its placeholder describes the input?
A: A placeholder disappears as someone types and is not a dependable replacement for a label. Associate a visible label with the input using matching for and id attributes. If space truly requires hiding it, preserve an accessible name.

FS004 | Semantic HTML | junior
Q: How do main, nav, and aside help users beyond making markup readable?
A: These elements can expose meaningful landmarks to assistive technology. Main identifies primary content, nav identifies a major navigation region, and aside marks complementary content. Use them according to purpose rather than wrapping every small component in a landmark.

FS005 | Semantic HTML | junior
Q: Should a pricing comparison use a table or a collection of layout divs?
A: Use a table when the information genuinely has row and column relationships. Associate headers with the corresponding cells and provide a useful caption. Use layout primitives for positioning rather than tables when no tabular relationship exists.

FS006 | Semantic HTML | junior
Q: What is the difference between meaningful and decorative image alternatives?
A: A meaningful image needs alternative text that communicates its purpose in context. A purely decorative image normally uses an empty alt attribute so it can be skipped. Avoid repeating nearby text or describing irrelevant visual details.

FS007 | Semantic HTML | junior
Q: Why can adding ARIA roles to native controls make an interface worse?
A: An inappropriate role can replace useful native semantics without supplying the required behavior. Prefer native elements and add ARIA only where necessary. A role describes an interaction contract; it does not automatically implement keyboard handling or focus management.

FS008 | Semantic HTML | junior
Q: How would you mark up a grouped set of shipping choices?
A: Use radio inputs sharing a name when exactly one option may be selected. Group related controls with a fieldset and an informative legend. Associate each option with its own label so the group and individual choices are understandable.

FS009 | Semantic HTML | junior
Q: When is an ordered list preferable to a series of paragraphs?
A: Use an ordered list when sequence or rank is meaningful, such as installation steps. Use an unordered list for a collection without inherent order. List semantics communicate grouping and item counts more reliably than manually inserted symbols.

FS010 | Semantic HTML | junior
Q: What problems can duplicate HTML id values cause in a reusable component?
A: Duplicate IDs can make label associations, fragment navigation, and scripting target the wrong element. Generate stable unique identifiers when multiple instances can coexist. Test the component rendered more than once rather than only in isolation.

FS011 | Accessible interaction | junior
Q: What should happen to focus when a modal dialog opens and closes?
A: Move focus to an appropriate element inside the dialog, keep interaction within a genuinely modal dialog, and restore focus sensibly when it closes. Provide a clear dismiss action and test keyboard navigation rather than relying on visual appearance.

FS012 | Accessible interaction | junior
Q: How can you make an asynchronous save result understandable without stealing focus?
A: Use an appropriate live status region to announce the result while retaining focus on the user's current task. Keep messages concise and avoid announcing every intermediate change. Reserve urgent announcements for conditions that genuinely require immediate attention.

FS013 | Accessible interaction | junior
Q: Why is removing the default focus outline a usability regression?
A: Keyboard users need to see which element will receive the next action. Replace the default outline only with another clearly visible focus indicator. Verify it against all backgrounds and ensure clipping or overlays do not hide it.

FS014 | Accessible interaction | mid
Q: How should keyboard behavior differ between tabs and ordinary navigation links?
A: Tabs switch between panels in a coordinated widget and commonly use arrow keys within the tab list. Navigation links follow normal document navigation. Do not apply tab roles to ordinary links unless you also implement the expected selection and panel relationships.

FS015 | Accessible interaction | junior
Q: Why is a red border alone insufficient to explain a validation failure?
A: Color alone does not convey the reason to all users. Provide explanatory text, associate it with the relevant control, and expose invalid state appropriately. The message should explain how to recover rather than merely saying something is wrong.

FS016 | Accessible interaction | mid
Q: How would you test a custom combobox for accessibility?
A: Test its accessible name, expanded state, active option, selection, and expected keyboard interactions. Check screen-reader behavior and focus during filtering and closing. Automated scans help find markup defects but cannot establish that the complete interaction is usable.

FS017 | Accessible interaction | junior
Q: How should an interface respond to a reduced-motion preference?
A: Reduce nonessential movement and provide alternatives to animations that convey important information. A reduced-motion preference does not necessarily mean removing every transition. Preserve comprehension and test whether disabling motion changes timing assumptions or hides completion feedback.

FS018 | Accessible interaction | junior
Q: Why should icon-only toolbar buttons have explicit accessible names?
A: The icon's appearance may not communicate its purpose to assistive technology or unfamiliar users. Give each button a concise action name and provide visible clarification where helpful. Avoid names that describe the icon instead of the action.

FS019 | Accessible interaction | mid
Q: What accessibility concerns arise when a list is virtualized?
A: Offscreen items may not exist in the document, affecting search, reading order, focus, and assistive navigation. Preserve focused items where appropriate and expose useful collection information. Test the actual reading and keyboard experience instead of assuming fewer nodes are always better.

FS020 | Accessible interaction | junior
Q: What is a skip link and when does it become useful?
A: A skip link lets keyboard users bypass repeated navigation and jump to primary content. Make it discoverable when focused and ensure its target receives an appropriate navigation outcome. It is especially useful on pages with long repeated headers.

FS021 | CSS layout | junior
Q: When would you choose Grid over Flexbox for a dashboard?
A: Grid is useful when rows and columns need coordinated two-dimensional alignment. Flexbox is useful for distributing items along one principal axis. They work well together: a dashboard can use Grid globally and Flexbox inside each card.

FS022 | CSS layout | junior
Q: Why can a flex child overflow even when its parent has available shrinking space?
A: A flex item's automatic minimum size can preserve its content width and prevent shrinking as expected. Inspect minimum sizes and overflow behavior; setting min-width to zero may be appropriate. Also handle long unbroken content rather than masking it globally.

FS023 | CSS layout | junior
Q: How does border-box sizing simplify component dimensions?
A: With border-box, the declared width includes padding and borders, making layout calculations more predictable. Margins remain outside that width. Understand the sizing model when mixing components so added padding does not unexpectedly expand a constrained element.

FS024 | CSS layout | mid
Q: Why might a sticky sidebar fail to stick while scrolling?
A: Inspect the sidebar's inset, available travel distance, and scrolling ancestors. An ancestor's overflow behavior may change which container governs sticky positioning. Also check whether the containing block is too short to allow the expected movement.

FS025 | CSS layout | mid
Q: Why does an enormous z-index sometimes fail to place a menu above another panel?
A: Z-index is resolved within stacking contexts, not across one global numeric ordering. Properties such as transforms or opacity can create separate contexts. Inspect the ancestor contexts and consider a suitable overlay root rather than continually increasing the number.

FS026 | CSS layout | junior
Q: How can you center a loading message without absolute positioning?
A: Use a flex or grid container with appropriate alignment properties and an intentional available height. This preserves normal layout behavior and usually adapts better to changing content. Avoid a fixed height if text wrapping or zoom should expand the container.

FS027 | CSS layout | junior
Q: What is the practical difference between gap and margins in a wrapping layout?
A: Gap creates spacing between layout items without adding outer spacing around the container. Margins belong to individual elements and can affect edges differently. Choose deliberately, particularly when wrapping changes which items appear at the start of a row.

FS028 | CSS layout | junior
Q: How would you preserve the shape of media before it finishes loading?
A: Provide intrinsic dimensions or a suitable aspect ratio so the browser can reserve space. Choose object-fit behavior based on whether cropping is acceptable. Reserving layout space reduces visible jumps without requiring the resource to finish downloading first.

FS029 | CSS layout | mid
Q: When is absolute positioning a good choice, and when does it create fragile layouts?
A: It suits overlays or decorations positioned relative to a known containing block. It becomes fragile for primary content whose size changes with text, localization, or viewport width. Keep ordinary document content in flow unless there is a clear reason not to.

FS030 | CSS layout | junior
Q: Why might width: 100vw introduce horizontal scrolling?
A: Viewport units can include space that does not match the available content width, including scrollbar-related differences. Added padding or borders can also expand the element. Prefer a container-relative width when the intent is simply to fill the parent.

FS031 | Responsive design | junior
Q: How should you choose breakpoints for a responsive page?
A: Choose breakpoints where the content or interaction needs a different arrangement, not merely from a list of popular devices. Resize continuously and test intermediate widths. Content length, zoom, and input methods matter as much as screen dimensions.

FS032 | Responsive design | mid
Q: When are container queries more useful than viewport media queries?
A: Container queries let a component adapt to its allocated space even when the viewport stays unchanged. This helps reusable cards in sidebars and main columns. Use viewport queries for page-level concerns and establish an appropriate containment context for component queries.

FS033 | Responsive design | junior
Q: How would you make a dense data table usable on a narrow screen?
A: Preserve the relationships users need, potentially using a labeled horizontal scroll region or a carefully designed alternate presentation. Do not hide essential columns arbitrarily. Test keyboard access, column headers, and whether comparing values remains practical.

FS034 | Responsive design | junior
Q: Why can fixed-height cards fail when a user increases text size?
A: Text may wrap onto additional lines and overflow, overlap, or disappear inside the fixed height. Prefer content-driven sizing or carefully chosen minimum heights. Test zoom and larger text settings rather than only the default font and sample copy.

FS035 | Responsive design | junior
Q: How do srcset and sizes help responsive image delivery?
A: They let the browser choose an image candidate using the intended display size and device characteristics. Provide truthful sizes information and appropriate candidates. CSS still controls layout; these attributes mainly help avoid downloading unnecessarily large or inadequate images.

FS036 | Responsive design | mid
Q: What should change for a touchscreen interface beyond its layout width?
A: Consider target size, spacing, lack of hover, and gesture conflicts. A narrow screen does not prove touch input, and a wide screen does not prove mouse input. Ensure essential actions work across input methods rather than hiding them behind hover.

FS037 | Responsive design | junior
Q: How can clamp make typography flexible without becoming unreadably small?
A: Clamp allows a preferred fluid value within explicit minimum and maximum bounds. Select those bounds around readable content rather than visual effect alone. Test zoom behavior and avoid formulas that effectively prevent users from enlarging text.

FS038 | Responsive design | mid
Q: Why might a mobile page jump when browser controls appear or disappear?
A: The available viewport can change as browser chrome or an on-screen keyboard changes. Traditional viewport-height assumptions may not match the intended visible area. Consider newer viewport units where supported and test scrolling and input focus on actual mobile browsers.

FS039 | Responsive design | junior
Q: What is the tradeoff in turning desktop navigation into a collapsed mobile menu?
A: Collapsing saves space but makes destinations less immediately discoverable and introduces another interaction. Keep the trigger clear and preserve keyboard and focus behavior. Consider which high-value destinations should remain visible rather than collapsing everything by habit.

FS040 | Responsive design | junior
Q: How would you diagnose horizontal overflow without hiding overflow on the entire page?
A: Inspect which element extends beyond the viewport, then examine fixed widths, minimum sizes, long strings, and positioned children. Fix the source with suitable wrapping or sizing rules. Global clipping can conceal inaccessible content instead of solving the layout problem.

FS041 | Forms and validation | junior
Q: Why is browser-side form validation useful if the server must validate again?
A: Client validation gives quick feedback and prevents avoidable round trips. Server validation remains authoritative because clients can be modified and business state can change. Share clear contracts where useful without treating browser checks as an authorization or integrity boundary.

FS042 | Forms and validation | junior
Q: Should validation errors appear while typing, on blur, or after submission?
A: Choose timing based on the field and interruption cost. Avoid showing errors before someone has had a reasonable chance to enter valid input. After submission, make failures easy to locate and preserve entered values for correction.

FS043 | Forms and validation | junior
Q: What is the difference between disabling a field and making it read-only?
A: Disabled controls generally cannot be interacted with and are not included in native form submission. Read-only text controls remain available for focus and submission. Select the behavior that matches the workflow rather than using either state solely for styling.

FS044 | Forms and validation | mid
Q: How should a form handle a server validation error after passing local checks?
A: Map field-specific errors to their controls and present other failures at form level. Preserve values and explain recovery. Server conditions may have changed, so a local success does not mean a later rejection is necessarily a frontend defect.

FS045 | Forms and validation | junior
Q: Why should a save button communicate pending state instead of simply disappearing?
A: Users need confirmation that their action was received and is still processing. Keep a clear pending indication and prevent accidental duplicate submissions where appropriate. Preserve layout and announce completion or failure so users do not have to infer the outcome.

FS046 | Forms and validation | mid
Q: How would you support a form with dependent country and region fields?
A: Define what happens to an existing region when its country changes, and load new options without letting stale responses overwrite current choices. Represent loading and unavailable states explicitly. Validate that the final pair is coherent on the server.

FS047 | Forms and validation | junior
Q: Why should a phone number usually not use a numeric input type?
A: Phone numbers are identifiers with formatting, prefixes, and sometimes leading zeros, not quantities for arithmetic. A telephone input can request a suitable keyboard without imposing numeric semantics. Validation must account for the regions and formats the application supports.

FS048 | Forms and validation | mid
Q: How can autofill affect a form that was only tested through manual typing?
A: Autofill may populate several fields at once and interact differently with event handling or visual labels. Use appropriate autocomplete attributes and test saved values in real browsers. Avoid assuming every meaningful change follows the same keystroke sequence.

FS049 | Forms and validation | junior
Q: How should resetting a form differ from clearing every visible control?
A: A reset usually restores defined initial values rather than making every value empty. Also reset validation and submission state where appropriate. Confirm the intended behavior for edited records so a reset does not silently discard more work than expected.

FS050 | Forms and validation | mid
Q: What must a multi-step form preserve when users move backward?
A: Preserve relevant entries, validation context, and a predictable focus destination. Define whether later answers remain valid when earlier choices change. Do not make backward navigation silently submit or erase data, and offer a review step for consequential submissions.

FS051 | JavaScript values | junior
Q: Why can two objects with identical properties compare unequal with strict equality?
A: Strict equality compares object identity, not structural content. Separately created objects have different references even when their properties match. Choose a deliberate comparison strategy for the domain rather than assuming JSON serialization is a universal deep-equality operation.

FS052 | JavaScript values | junior
Q: When should nullish coalescing replace logical OR for a default value?
A: Use nullish coalescing when only null and undefined mean missing. Logical OR also replaces valid falsy values such as zero, false, and an empty string. Decide which values are legitimate before choosing the defaulting expression.

FS053 | JavaScript values | junior
Q: Why does spreading an object not fully isolate its nested data?
A: Object spread creates a shallow copy, so nested objects and arrays remain shared references. Updating those nested values can still affect the original. Copy along changed paths or use a suitable cloning strategy with clearly understood supported types.

FS054 | JavaScript values | junior
Q: What makes floating-point arithmetic unsuitable for naive money calculations?
A: Many decimal fractions are not represented exactly in binary floating point. Repeated arithmetic can expose rounding differences. Use a domain-appropriate representation, such as validated minor units or a decimal library, and define rounding rules explicitly.

FS055 | JavaScript values | junior
Q: How does a Map differ from an ordinary object used as a lookup?
A: A Map accepts keys of different types and has dedicated size and iteration APIs. Ordinary objects have property-key coercion and prototype behavior to consider. Choose based on the contract, and use safe own-property handling when accepting arbitrary dictionary keys.

FS056 | JavaScript values | mid
Q: Why can an array with empty slots behave differently from one containing undefined?
A: An empty slot is a missing indexed property, while an explicit undefined value is still an element property. Some iteration methods skip holes. Validate density when algorithms require one value per position, and test sparse arrays deliberately.

FS057 | JavaScript values | junior
Q: What should you consider before using sort on data received through props?
A: Array sort mutates its receiver, which can unexpectedly change shared data. Copy the array first or use a supported nonmutating alternative. Supply a comparator suitable for the values rather than relying on default string-based ordering.

FS058 | JavaScript values | mid
Q: Why can a date-only string produce an unexpected displayed calendar day?
A: Date parsing and display can apply different time-zone assumptions, shifting the observed day. Distinguish calendar dates from instants. Preserve date-only values as date-only data when appropriate, and explicitly choose zones when formatting timestamps.

FS059 | JavaScript values | junior
Q: When is optional chaining helpful, and what errors can it conceal?
A: Optional chaining safely stops access through null or undefined where absence is expected. It does not validate types or guarantee later operations are meaningful. Using it everywhere can hide broken invariants that should instead trigger explicit handling.

FS060 | JavaScript values | junior
Q: Why is JSON parsing not sufficient validation of an API response?
A: Parsing proves that the text has valid JSON syntax, not that it matches the expected fields, types, or business rules. Validate the decoded value at the boundary and distinguish malformed transport data from an ordinary empty result.

FS061 | Functions and modules | junior
Q: How does a closure help implement a debounced search callback?
A: A closure lets the callback retain access to timer state across invocations. Each new call can replace the pending timer. Define cancellation and cleanup behavior so delayed work does not continue after the owning component or interaction ends.

FS062 | Functions and modules | junior
Q: Why can passing an object method as a callback change its behavior?
A: A method's this value depends on how it is called, not simply where it was defined. Passing it as an unbound function can lose the receiver. Bind deliberately or use a wrapper that preserves the required context.

FS063 | Functions and modules | mid
Q: How do you distinguish a pure transformation from a function with side effects?
A: A pure transformation produces its result from its inputs without changing external state. Side effects include storage writes, network calls, and mutation of shared objects. Isolating transformations often makes testing easier while keeping effects explicit at application boundaries.

FS064 | Functions and modules | junior
Q: What belongs in a module's public API rather than being exported for convenience?
A: Export the stable operations and types that consumers genuinely need. Keep implementation details private so they can change without breaking callers. A smaller public surface makes dependencies easier to understand and reduces accidental coupling between features.

FS065 | Functions and modules | mid
Q: Why can circular module imports cause initialization problems?
A: Modules in a cycle may observe dependencies before the expected initialization has completed. Exact behavior depends on the module system and evaluation order. Break the cycle by separating shared contracts or moving coordination to a higher-level module.

FS066 | Functions and modules | junior
Q: When is a dynamic import useful in a web application?
A: Dynamic import can load code when a route or feature is needed rather than including it in the initial bundle. Handle loading and failure states. Excessive fragmentation can create request overhead and sequential loading delays, so measure the result.

FS067 | Functions and modules | mid
Q: What is stale captured state in a callback?
A: A callback may retain values from the render or scope in which it was created while the application has moved on. Decide whether it should use a snapshot or current state. Update dependencies, use functional updates, or use an appropriate mutable reference.

FS068 | Functions and modules | junior
Q: Why are default parameter values not a replacement for input validation?
A: A default parameter primarily handles undefined arguments. It does not reject wrong types, invalid ranges, or incompatible combinations. Validate external inputs explicitly and use defaults only when the missing-value behavior is part of the documented contract.

FS069 | Functions and modules | mid
Q: How can dependency injection make a browser utility easier to test?
A: Pass dependencies such as a clock, storage adapter, or request function instead of reading globals everywhere. Tests can provide controlled implementations while production uses real services. Keep the interface focused so injection does not become unnecessary framework complexity.

FS070 | Functions and modules | junior
Q: Why should a utility name describe its result or effect instead of its implementation?
A: Callers need to understand what the function promises, not its current loop or library choice. Names tied to implementation become misleading after refactors. Include meaningful effects in the contract so a seemingly harmless helper does not hide persistence or network activity.

FS071 | DOM and events | junior
Q: How does event delegation help a list with many interactive rows?
A: A listener on a common ancestor can handle bubbled events from multiple descendants. Determine the intended control using the event path or an appropriate closest lookup. Check containment and avoid assuming the direct target is always the button itself.

FS072 | DOM and events | junior
Q: What is the difference between preventDefault and stopPropagation?
A: PreventDefault requests cancellation of a cancelable event's default action. StopPropagation prevents further propagation through the event path but does not itself cancel that action. Use each for a specific reason rather than applying both to every handler.

FS073 | DOM and events | mid
Q: Why might a passive touch listener ignore a call to preventDefault?
A: A passive listener promises that it will not cancel the event, allowing browser scrolling optimizations. Calling preventDefault violates that promise and is ineffective there. Use appropriate touch-action rules and choose listener options based on the interaction's real needs.

FS074 | DOM and events | junior
Q: When should a component remove a global event listener?
A: Remove it when the component or behavior no longer owns the subscription. Retain the function identity needed for removal and match relevant options. Repeated setup without cleanup can create duplicate actions and keep otherwise unused objects reachable.

FS075 | DOM and events | mid
Q: Why can an Enter-key submit handler break input through an IME?
A: Enter may confirm a composition candidate rather than indicate intent to submit. Account for composition state and test the relevant input sequence. Treat text entry as more than individual key presses, especially for languages using composition-based input.

FS076 | DOM and events | junior
Q: Why is textContent safer than HTML insertion when displaying plain user text?
A: TextContent treats the value as text rather than interpreting markup. HTML insertion requires a separate trust and sanitization decision. Use ordinary text rendering when formatting is unnecessary, and do not assume escaping one context makes a value safe everywhere.

FS077 | DOM and events | mid
Q: What is pointer capture useful for in a draggable splitter?
A: Pointer capture keeps subsequent pointer events directed to the capturing element during an interaction even when the pointer leaves its bounds. Handle release and cancellation cleanly. It does not remove the need for keyboard alternatives or sensible touch behavior.

FS078 | DOM and events | junior
Q: Why should DOM measurements and style writes be grouped carefully?
A: Alternating layout-dependent reads with writes can force repeated synchronous layout work. Gather needed measurements, calculate changes, and apply updates together where practical. Measure actual performance before adding elaborate scheduling that obscures a simple interaction.

FS079 | DOM and events | mid
Q: When would you use ResizeObserver instead of listening only for window resize?
A: An element can change size because of content or surrounding layout without the window resizing. ResizeObserver follows the element itself. Avoid feedback loops where the observer repeatedly changes the same dimensions it observes, and disconnect subscriptions during cleanup.

FS080 | DOM and events | junior
Q: How does a browser event's target differ from currentTarget?
A: Target identifies the originating event target, subject to retargeting rules. CurrentTarget identifies the object whose listener is currently running. In a delegated handler, these often differ, so choose deliberately when reading attributes or updating the intended control.

FS081 | Asynchronous UI | junior
Q: Why does awaiting a promise not make a long CPU calculation responsive?
A: Await yields while a promise is pending, but synchronous computation still occupies the thread when it runs. Break work into manageable tasks or move suitable computation to a worker. Wrapping an expensive loop in a promise alone does not solve blocking.

FS082 | Asynchronous UI | mid
Q: How can an older search response overwrite newer search results?
A: Requests may finish in a different order from when they started. Associate responses with the current query or request generation and ignore obsolete results. Cancellation helps reduce unnecessary work, but explicit relevance checks remain useful when cancellation is not guaranteed.

FS083 | Asynchronous UI | junior
Q: When should independent API requests be started together?
A: Start independent requests together when doing so reduces latency without overwhelming the service or client. Awaiting them sequentially creates unnecessary delay. Keep truly dependent requests ordered and decide whether one failure should discard or preserve other successful results.

FS084 | Asynchronous UI | junior
Q: How does Promise.allSettled support a partially available dashboard?
A: It reports each input promise's outcome without rejecting solely because one request failed. The interface can display successful panels and localized failures. This does not automatically provide timeouts, retries, or dependency handling; those still need deliberate policy.

FS085 | Asynchronous UI | mid
Q: What should happen when a user navigates away during an upload?
A: Define whether the upload is canceled, continues in an application-level owner, or requires a warning about interruption. Release component subscriptions either way. Do not equate closing the view with proof that the server stopped processing the request.

FS086 | Asynchronous UI | junior
Q: What is the difference between debouncing and throttling user-driven work?
A: Debouncing waits for a quiet period, making it useful for settled input. Throttling limits execution frequency while activity continues. Choose based on whether the interface needs a final value, periodic feedback, or both, and define trailing-call behavior.

FS087 | Asynchronous UI | mid
Q: Why can repeatedly queueing microtasks delay rendering?
A: Browsers generally drain the microtask queue before proceeding to other event-loop work, including rendering opportunities. A chain that keeps adding microtasks can monopolize progress. Yield through an appropriate task boundary when substantial work must be divided for responsiveness.

FS088 | Asynchronous UI | junior
Q: How would you distinguish loading, empty, and failed states in a results view?
A: Model them as separate outcomes instead of using an empty array to mean all three. Loading means the result is unresolved, empty means a successful query found nothing, and failed means the result could not be obtained. Offer appropriate guidance for each.

FS089 | Asynchronous UI | mid
Q: When is an optimistic update a poor fit?
A: Avoid assuming success when a failed operation is costly, common, or difficult to reverse clearly. Optimism works best with predictable actions and a coherent reconciliation strategy. Communicate pending status and define what users see when the server rejects the change.

FS090 | Asynchronous UI | mid
Q: What should a retry button preserve after a transient request failure?
A: Preserve the user's intended input and enough request context to retry the same action safely. Determine whether the previous attempt may have succeeded before repeating a mutation. Avoid regenerating identifiers or silently changing parameters in ways that alter the operation.

FS091 | HTTP in the browser | junior
Q: Why does fetch require checking response status even when no exception was thrown?
A: Fetch usually resolves when an HTTP response arrives, including many error status codes. Check response.ok or the expected status before treating the body as success. Network failures and aborted requests are different from a server's explicit rejection.

FS092 | HTTP in the browser | junior
Q: What should a client do with a successful 204 response?
A: A 204 response has no response content to parse. Handle the documented success outcome without unconditionally calling a JSON parser. Design response handling around the endpoint contract rather than assuming every successful request returns an object.

FS093 | HTTP in the browser | mid
Q: What does a CORS failure tell you, and what does it not prove?
A: It indicates that browser cross-origin access requirements were not satisfied for that interaction. It does not by itself prove the server was unreachable or that no request reached it. Inspect preflight and actual request behavior separately using browser diagnostics.

FS094 | HTTP in the browser | junior
Q: Why should URL parameters be encoded using URL APIs rather than string concatenation?
A: Parameter values may contain separators, spaces, or characters with special meaning in a URL. URL and URLSearchParams handle serialization more reliably. Still validate the resulting destination and avoid confusing encoding with authorization or general input validation.

FS095 | HTTP in the browser | mid
Q: How can credentials configuration affect a cross-origin browser request?
A: The request's credentials mode affects whether browser-managed credentials are sent or accepted in relevant contexts. The server must also satisfy the applicable cross-origin rules. Cookie attributes and browser privacy policies can further limit behavior, so test the complete configuration.

FS096 | HTTP in the browser | junior
Q: Why is application/json not the correct content type for every request body?
A: The content type describes the actual representation being sent. FormData, text, and binary payloads have different formats and handling requirements. When using FormData, let the browser generate its multipart boundary rather than inventing a mismatched header.

FS097 | HTTP in the browser | mid
Q: How should a frontend treat a 429 response?
A: Explain that the action is temporarily limited and respect a valid retry policy, including applicable Retry-After guidance. Avoid immediate retry loops. Preserve user intent where practical and coordinate retries so multiple interface components do not intensify the overload.

FS098 | HTTP in the browser | junior
Q: What is the difference between a network timeout and a server-declared business rejection?
A: A timeout leaves uncertainty about whether processing completed, whereas an explicit business response reports a defined outcome. Present different recovery guidance and avoid blindly repeating consequential actions. Use request identifiers or status reconciliation where the operation requires certainty.

FS099 | HTTP in the browser | mid
Q: Why can a redirect change the behavior of an API request unexpectedly?
A: Redirect handling can affect the destination, method behavior for particular status codes, credentials, and response format. A request expecting JSON might eventually receive a login page. Inspect the final response and use explicit authentication failure contracts for APIs.

FS100 | HTTP in the browser | junior
Q: What information is useful when reporting a failed browser API call?
A: Record the operation, status or network error, approximate timing, and a safe correlation identifier. Exclude secrets and unnecessary personal data. Separate the user's action from low-level details so engineers can connect the failure to the relevant server logs.

FS101 | Browser caching | junior
Q: How does a fresh cached response differ from a revalidated response?
A: A fresh cached response can be reused under its caching rules without contacting the server. Revalidation checks whether stored content remains usable. This distinction explains why some requests avoid network transfer while others still incur a round trip.

FS102 | Browser caching | mid
Q: What is the difference between no-cache and no-store?
A: No-cache permits storage but requires successful validation before reuse under its rules. No-store directs caches not to store the message. Choose based on sensitivity and reuse requirements rather than interpreting the names as interchangeable commands to disable caching.

FS103 | Browser caching | junior
Q: Why do hashed asset filenames work well with long cache lifetimes?
A: A content change produces a new URL, allowing old assets to remain safely cached while new pages reference new versions. Keep the entry document's caching policy compatible with releases. A long-lived URL whose content changes needs another invalidation strategy.

FS104 | Browser caching | mid
Q: What role does an ETag play in conditional retrieval?
A: An ETag is a validator representing a selected resource representation. A client can send it in a conditional request so the server can indicate whether reuse is appropriate. It is not inherently a timestamp or a guarantee that the content is globally immutable.

FS105 | Browser caching | mid
Q: Why must shared caches distinguish responses that vary by language or encoding?
A: Different request characteristics may produce different representations at the same URL. Correct variation metadata lets caches avoid reusing an incompatible representation. Keep the variation set intentional because excessive variation reduces cache efficiency and complicates reasoning about reuse.

FS106 | Browser caching | junior
Q: Why can clearing a browser cache appear to fix a deployment without fixing its cause?
A: Clearing removes the stale combination currently visible to that browser. Incorrect cache headers, release ordering, or service-worker behavior may still affect other users. Diagnose the invalidation contract and version relationships instead of relying on manual clearing as the permanent solution.

FS107 | Browser caching | mid
Q: How does an application query cache differ from the HTTP cache?
