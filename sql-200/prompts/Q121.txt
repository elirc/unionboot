Q121 — family SQLite schema constraints and integrity, scenario 1: integer-primary-key-rowid-alias

Task
SQLite-specific: create items(id INTEGER PRIMARY KEY,name TEXT NOT NULL). Insert One without id, then select id,name ordered by id. The grader also checks generated id and required name.

Dialect: SQLite, executed with Node node:sqlite DatabaseSync. SQLite date/string functions, dynamic typing, rowid/INTEGER PRIMARY KEY, booleans-as-integers, PRAGMAs and query-plan text are SQLite-specific, not portable SQL promises.

Seed schema and data (a fresh in-memory database for every run; foreign_keys=ON)
CREATE TABLE departments(id INTEGER PRIMARY KEY); INSERT INTO departments VALUES(10),(20);

Concrete example
With the exact seed above, the first result row is {"id":1,"name":"One"}.

Expected shape
Columns (exact aliases): id, name. 1 row(s); exact order below is graded. NULL is JSON null; SQLite numeric results become JavaScript numbers.
[
  {
    "id": 1,
    "name": "One"
  }
]

Integrity checks after the result assertion (these exercise constraints/state, not helper solution SQL):
[
  {
    "sql": "INSERT INTO items(name) VALUES(NULL)",
    "reject": "NOT NULL"
  },
  {
    "sql": "SELECT rowid,id FROM items",
    "expected": [
      {
        "id": 1
      }
    ]
  }
]
