W285 — Idempotency key POST contracts
Scenario 5/10: Key limit 12; replay 200, creation 201

Handle deterministic sequential POSTs using supplied in-memory Store (not concurrency-safe; persistence/auth scope outside exercise). Require one nonblank Idempotency-Key <=12 UTF-16 units, preserve exact key. Missing/duplicate/too long ->400, no write. New key ->201 Location /submissions/ID with {id,payload}, increment ID once. Same key/payload ->200 same response data; changed payload->409 without mutation. Empty payload valid. Example k + "a" then k + "a" ->201 then200, one record.

Signature: public static IResult Handle(HttpRequest request, string payload, Store store)
Provided domain types: public sealed record Saved(int Id,string Payload); public sealed class Store {public int NextId;public Dictionary<string,Saved> Records {get;}=new(StringComparer.Ordinal);}
